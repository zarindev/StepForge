# StepForge — Implementation Plan

_By Md Zarin Tasnim · part of the StepForge documentation_

> Record once. Test every layer. Export anywhere.

This plan is the working contract for building StepForge phase by phase. Progress is tracked
in [PROGRESS.md](PROGRESS.md); deviations and unverifiable behaviour in [KNOWN_ISSUES.md](KNOWN_ISSUES.md).

## Key technical decisions

| Decision | Choice | Why |
|---|---|---|
| Package layout | npm workspaces: `apps/*`, `packages/*`, `packages/executors/*`, `demo/*` | No extra tooling (no pnpm/turbo needed) |
| TS execution | Workspace packages export their `src/index.ts`; the server/CLI run through `tsx` | No per-package build step, one `tsc --noEmit` for the whole repo |
| Module format | ESM everywhere (`"type": "module"`), `moduleResolution: Bundler` | Works for Vite, tsx and Vitest alike |
| Own storage | `better-sqlite3` + Drizzle ORM, SQL migrations generated by `drizzle-kit`, applied on boot after a backup | Single file DB, zero servers |
| IDs | ULID (`ulid` package) | Sortable, URL-safe |
| UI | React 18 + Vite + Tailwind v4 + hand-written shadcn-style primitives + TanStack Router/Query | shadcn components are copied in, not installed — kept in `apps/web/src/components/ui` |
| Auth between UI and server | Random session token per server start, injected into `index.html`, required as `x-stepforge-token` header and WS query param | Blocks other local sites (CSRF/DNS rebinding) from driving the API |
| Bind address | `127.0.0.1` only (hard-coded check refuses `0.0.0.0`) | Local-first constraint |
| Secrets | AES-256-GCM, 32-byte master key at `data/.key` (mode 0600) | Section 9 |

## Phase map

| # | Phase | Key deliverables |
|---|---|---|
| 1 | Foundation | monorepo, `@stepforge/core` (Zod step model + entity schemas + variable resolver), `@stepforge/db` (full Drizzle schema, migrations, backup-before-migrate), `@stepforge/crypto`, Fastify server (token auth, health, WS, static UI), React shell (rail, routes, empty states), setup/start scripts, CI |
| 2 | Organisation | apps/envs/secrets/modules/tags CRUD, Test Explorer tree, scenarios/steps/test cases, version history |
| 3 | Engine + UI executor | scenario engine, executor plugin registry, Playwright executor, job queue, live run view, artifacts, results view |
| 4 | Recorder | injected Shadow-DOM toolbar, locator ranking, network capture, Scenario Editor list/flow/plain-English |
| 5 | API | API executor, API client UI, importers (OpenAPI/Postman/cURL/HAR), contract checks |
| 6 | Database | DB executor (pg/mysql/mssql/sqlite/mongo), SQL workbench, data-quality audit, rollback mode |
| 7 | Email | Mailpit + IMAP adapters, OTP/link extraction |
| 8 | Performance | web-vitals, Lighthouse, load engine (autocannon), k6 export/bridge, query plans |
| 9 | Diagnosis + bugs | rule engine (YAML), last-green diff, bug reports, PDF/XLSX/CSV/MD/JUnit/HTML exports |
| 10 | Analytics | dashboards, quality gates, run comparison, flaky detection |
| 11 | Automation | scheduler, CLI, notifications |
| 12 | Codegen | Playwright/Cypress/Selenium/API/docs/CI generators + snapshot tests |
| 13 | Polish | README, docs, onboarding, fresh-clone verification |
| 14 | Showcase | screenshots, samples, case-study slides + exports, optional Electron |

Demo apps (CareClinic, ShopDesk) are built alongside Phase 3–4 so every later phase can be
validated against them.
