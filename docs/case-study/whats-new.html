StepForge2/15
01 · Manual testing

Test by hand, with StepForge beside you.

  • Run manually opens your app with a step panel
  • Current step, expected result and the next step
  • Pass, fail, blocked or skip — with notes
  • Screenshots and a recorded session
Free & open source — by Md Zarin Tasnim
StepForge3/15
02 · Mark up and report

From a failed step to a clear bug report.

  • Boxes, circles, arrows, pen and text in any colour
  • How it should behave vs how it behaves
  • Steps to reproduce filled in for you
  • Manual tests stay pending; schedules skip them
Free & open source — by Md Zarin Tasnim
StepForge4/15
03 · Visual checkpoints

Catch visual regressions.

  • The first run saves the approved screenshot
  • Pixel comparison with a red difference image
  • Accept as new baseline in one click
  • Hide clocks, ads and avatars before comparing
Free & open source — by Md Zarin Tasnim

04 · Any web app

Test any kind of web app.

  • Wait for or fake API responses · go offline
  • Downloads · cookies & storage · control the clock
  • Mobile web with touch · clicks on canvas and maps
  • Per environment: language, time zone, location, dark mode, basic auth, proxy, certificates
Free & open source — by Md Zarin Tasnim
StepForge6/15
05 · Campaigns

One click: every environment × browser × size.

  • Saved test sets: all, modules, tags or scenarios
  • Each test's result per combination, side by side
  • Rerun only what failed, only where it failed
  • From the dashboard, a schedule or the CLI
Free & open source — by Md Zarin Tasnim
StepForge7/15
06 · Reusable blocks

Write "Sign in" once. Use it in every test.

  • Blocks with inputs and default values
  • Select steps → Make a block
  • Fix the block once: every test using it is repaired
  • Failures grouped by block
Free & open source — by Md Zarin Tasnim
StepForge8/15
07 · Before / after each test

Set-up and clean-up, automatically.

  • A block before and after every test of a module
  • Sub-modules inherit them; scenarios add their own
  • Clean-up runs even when the test fails
Free & open source — by Md Zarin Tasnim

08 · Element repository

Fix a locator once. Every step follows.

  • Named, shared UI elements with ranked locators
  • See every step that uses an element
  • The one-click diagnosis fix updates the element
  • Recordings reuse elements you already have
Free & open source — by Md Zarin Tasnim

Test data from tables, CSV, SQL or an API.

  • Named data sources, previewed in any environment
  • First, random, matching or not-yet-used rows
  • SQL sources only ever read
Free & open source — by Md Zarin Tasnim

10 · Page conditions

Tests that react to the page.

  • If the cookie banner is visible → accept it
  • Repeat while "Load more" is shown → click it
  • Visible, hidden, present, enabled, text, count
Free & open source — by Md Zarin Tasnim

11 · SOAP, Kafka and FTP

Test the systems behind your app.

  • SOAP calls with XPath checks and fault handling
  • Send and wait for Kafka messages
  • Upload, download and check files over FTP, FTPS, SFTP
  • All in plain English, next to UI and database steps

  • Failed tests with their diagnosis and a link
